快速开始（5 分钟跑通）

三步：① 在 API Console 创建 Key；② 提交生成任务拿到 taskId；③ 轮询或用 Webhook 取结果。

# 基础地址
https://api.llmport.ai/v1

# 鉴权头
X-API-KEY: $LLMPORT_KEY

鉴权

所有请求在 Header 携带 X-API-KEY。Key 在 API Console 创建与管理，可建多把（区分 prod / staging）。请勿在前端暴露。

提交生成任务

POST /v1/generation/{model_id}，请求体即该模型的 input。返回 taskId 与初始状态。

示例 cURLPythonNode 
curl -X POST https://api.llmport.ai/v1/generation/seedance-2.0 \
  -H "X-API-KEY: $LLMPORT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"input":{"prompt":"...","resolution":"720p","length":5,"aspectRatio":"9:16"}}'
# → { "taskId": "tk_8f3a", "status": "waiting" }

查询状态 / 取结果

轮询 GET /v1/generation/{taskId}/status 直到 succeed，结果含视频/图像 URL。失败不计费。

curl https://api.llmport.ai/v1/generation/tk_8f3a/status \
  -H "X-API-KEY: $LLMPORT_KEY"
# → { "status": "succeed", "url": "https://cdn.llmport.ai/...mp4", "billing": { "billable": true, "unit": "second", "quantity": 5 } }

状态机：waiting → processing → succeed（失败为 failed）。

Webhook（可选）

提交时带 webhookUrl，任务完成时网关会 POST 结果到你的地址，附 HMAC 签名头供验签——免去轮询。

从 fal 迁移

协议形状与状态机对齐 fal 的异步队列。多数情况下，迁移只需两步：

1
换 host
把 queue.fal.run 换成 api.llmport.ai。
2
换 key
把鉴权头换成你的 X-API-KEY，字段无需改动。
3
A/B 验证
小流量对比质量与成本，再逐步切量。
